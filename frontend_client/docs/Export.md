# Export / Print

Client-side export: `/projects/[id]/export` renders the canonical model as a printable document; **Print / Save as PDF** calls `window.print()` (browser dialog — see limitations). Related: [[Workspace-LLD]], [[Portal]], [[API-Client]].

## Flow

- Workspace header **Export** button → export route. Disabled while the workspace has no model (`model === null`) — you cannot export what does not exist.
- The route reuses the workspace query keys (`queryKeys.project` / `architecture`), so opening it right after the workspace is instant (shared cache). Access follows the D2 rule: project key **or** owner Bearer (`export-flow.tsx`).
- Refusal paths are JourneyShell error cards, never a blank sheet: no access, query failure (retry), `version === null` (no architecture yet), or `validation.valid === false` (export blocked — an invalid model must not print as a trusted document).

## Document sections (`export-document.tsx`)

Cover (idea, version, dates, validation verdict + counts) → requirements (functional/non-functional/clarifications/assumptions) → HLD (diagram + components + flows) → **sequence diagrams (one compact SVG per flow)** → LLD (diagram + classes + relationships + patterns) → DSA (`WorkspaceDsa`, flattened for paper) → learning steps → validation notes → footer. Every string derives from contract fields (`lib/export/document.ts`, unit-tested) — nothing is invented. **Raw contract ids never print**: rows are numbered instead (`fr_…`/`nfr_…`/`q_…`/`asm_…`, learning-step element refs, validation rule/path) — ids stay as React keys only. The relationship list resolves each endpoint through the model's classes (`relationshipRows` in `lib/export/document.ts`), so a line reads `RateLimiter → WindowStore` followed by `composition · 1 → 0..*` and the rationale; an endpoint that fails to resolve (impossible on a validated model) degrades to a placeholder — never a raw `cls_…` id. `.export-doc` also paints its own paper (`background-color` + `color` from the scoped tokens), otherwise the page shell's dark backdrop shows through and scoped text lands on it.

## Sequence diagrams (per flow)

- The 2026-11 review: HLD flows printed as prose only. Each flow now gets a **compact deterministic sequence diagram** in a `.export-sequence` figure, right after the Components/flows text section (portrait text page, flows with the surrounding text — never a named page of its own).
- Mapping lives in `lib/diagram/sequence-scene.ts` (`buildSequenceScene(model, flow)`, pure + unit-tested): participants are the flow's referenced components in **first-appearance order**; a resolvable connection ref contributes its from/to endpoints (and its kind), otherwise the step's first two component refs are the endpoints (**direction convention: with only component refs, the first listed ref is the sender**), a single component ref is a self-message, and a step whose refs resolve to nothing is **skipped — components are never invented**. Geometry: width `max(320, 160 + 110·participants)` (uncapped in scene space so ≥10 participants can never overlap their 72px box floor; CSS caps the rendered size), height `44 + 40·messages + 12`, so scenes are byte-stable for the same model.
- Rendering: `components/diagram/sequence-canvas.tsx` — static SVG (no pan/zoom, no new dependency): participant header boxes, dashed lifelines, arrows with sync/async/data line styles (same `HLD_EDGE_DASH` map as the HLD canvas), a primary **step-number badge** on each arrow, self-message loops on the free side of the lifeline, labels truncated to the arrow span, `role="img"` + `aria-label`. The SVG carries **native `width`/`height` attributes** from the scene: on screen CSS scales it up to the 640px text column (no overflow at 390px); in print `width: auto; max-width: 100%; max-height: 170mm` scales it **down from native size**, so a 2-participant × 20-step scene (226mm native, 381mm when upscaled) prints ≤170mm instead of overflowing the 273mm A4 portrait page.
- **Full step text as an ordered list** below each figure: because `role="img"` children are presentational (screen readers/print would only get the truncated arrow labels), every figure is followed by an `<ol>` of the same resolved messages — `1. Gateway -> Cache: gateway looks up the cache` — full description, direction from the resolved endpoints, no invented steps, no raw ids. The figure itself holds only heading + description + SVG + caption (always ≤ ~190mm, `break-inside: avoid`); the section is `break-inside: auto` so figures paginate between flows and the step list can break as ordinary text.
- The section **hides entirely when no flow resolves** (every step's refs are unknown), while the prose Flows list keeps describing the flow. The caption states `N of M steps shown` and says so when steps were skipped.
- Export-only: the workspace still renders the canonical architecture model, not flows-as-diagrams.

## Diagrams on paper

- The scene pipeline is the workspace's (`buildLldScene` / `buildHldScene`) with one export-only addition: `lib/export/orientation.ts` builds **both candidate rank directions** (LLD `BT` + `LR`, HLD `LR` + `TB`) and `pickByAspect` keeps the scene whose aspect (width/height) is closest to the printable box — `EXPORT_DIAGRAM_ASPECT = 1.5`, the landscape A4 content box — so fit-to-page scaling leaves the least whitespace (the 2026-11 review: tiny diagrams with huge whitespace came from a portrait-shaped scene in a landscape box). Ties keep the first candidate, i.e. the workspace default orientation; the workspace itself never passes `rankdir`, so its layout and tests are untouched. The chosen orientation and scene size publish on `.export-diagram` as `data-rankdir` / `data-scene` (`WxH`) for tests and debugging. The scenes render into `.export-diagram` boxes (620px tall on screen). Each diagram section (`.export-diagram-page`) prints on its **own A4 landscape page** (`@page export-diagram`), roughly 50% more width than portrait, so the fit-to-page scale stays legible. In print the box grows to **174mm** — the landscape printable height is 190mm (210mm − 2 × 10mm margin) and the heading measures ~16mm, so one diagram always fits one page while using ~92% of the printable height. The workspace marker/type legends are hidden on paper (`.diagram-legend`), handing that space to the drawing. `use-diagram-viewport` listens for `beforeprint` and re-fits the live SVGs to the print box; the print box is taller than the 620px screen box, so a missed refit cannot clip.
  - Ops fact: the named page must **not** be called `diagram`. Chromium 156 silently ignores a landscape `@page diagram` and prints portrait pages (found through `page.pdf` MediaBox inspection) — any other identifier works.
  - **Print-dialog reality**: the page cannot set the browser dialog's orientation or paper settings. `window.print()` opens the dialog with the CSS named-page defaults, but a dialog override (or a browser that ignores named pages) still yields portrait output — so the toolbar copy next to **Print / Save as PDF** tells the user honestly: enable **background graphics**, and if the diagram pages come out portrait, set **Orientation → Landscape**. The `page.pdf({ preferCSSPageSize: true })` test sees the CSS intent (two landscape MediaBox pages); it cannot prove what a user's dialog prints.
- **HLD + LLD only** (toolbar toggle, `aria-pressed`; renamed from "Diagrams only" because the document now also draws sequence diagrams and the toggle prints only the two landscape pages): `data-print-scope="diagrams"` hides every `.export-text-section` in print and drops the first/trailing page breaks, so printing emits **exactly the two landscape pages** (HLD + LLD) instead of the full report; toggling off restores the full document. The print button prints whichever scope is active.
- Canvas zoom controls carry `.no-print` (interaction chrome, not paper); legends are print-hidden as above.
- **Download SVG** (per diagram, next to its heading) serializes the live SVG with computed styles inlined (`lib/export/svg.ts`). It strips the fitted pan/zoom transform (`data-diagram-root`) and writes the scene's native `viewBox`/`width`/`height`, so the file is the full-resolution fallback; the print toolbar states this next to **Print / Save as PDF**.
- **Back to workspace** in the header resolves the route id client-side (`components/export/back-to-workspace.tsx`, `useParams` inside Suspense) — never a params-promise cast.

## Light theme + print rules (`globals.css`)

- **On screen the export page stays in the app's dark brand theme** (user decision: no white page); `.export-doc` only paints its surface from the active tokens (`background-color`/`color`), which keeps every heading/meta/diagram text visible instead of blending into the shell.
- **Print flips to light paper**: `@media print` re-scopes the full token set once (`.export-doc` + `:root`), so text, utilities, and SVG fills print as dark-on-white under any app theme. Also in the print block: hide `.no-print` chrome (header, buttons, canvas zoom controls) and `.diagram-legend`; release the content width to the page, `break-inside: avoid` on sections/diagrams/definition rows (with the sequence exception below), `break-after: avoid` on headings, `thead { display: table-header-group }`. `@page { size: A4; margin: 12mm 10mm }`, `@page export-diagram { size: A4 landscape; margin: 10mm }`, `.export-diagram { height: 174mm }` in print, plus the `[data-print-scope="diagrams"]` hiding/pagination rules for the HLD + LLD-only mode. **Sequence print rules**: `.export-sequence-section { break-inside: auto }` overrides the generic section avoid (the rule is re-asserted later in the print block, so the override sits after it) so multiple flow figures paginate between figures; each `.export-sequence` figure stays `break-inside: avoid`; `.export-sequence svg { width: auto; height: auto; max-width: 100%; max-height: 170mm }` prints at native scene size scaled down to fit — never up.
- Ops note: **restart `npm run dev` after CSS-only edits** — globals.css HMR misses served stale print/light rules twice.

## Limitations (deliberate)

- **Browser print dialog, not one-click PDF.** One-click would need jsPDF/html2canvas (poor SVG fidelity) or server-side Playwright rendering — deferred until users ask.
- **Page numbers** come from the browser's print header/footer option; Chromium ignores `@page` margin-box counters.
- **Large diagrams scale to fit one page** (fit-to-page, both dimensions) — no clipping, but a 40-class LLD can get small. Rank-based pagination across pages is *not* implemented; split it if users hit it.
- **Sequence diagrams are derived, not authored**: arrows come only from each step's `elementRefs` (connection refs → its from/to, else the first two component refs — with only component refs the **first listed ref is the sender**); a step with no resolvable component is skipped and reported in the caption, a lone participant renders self-messages, and labels truncate to the arrow span (the full text lives in the per-message SVG `<title>` **and** in the visible ordered step list under each figure, which doubles as the accessible/print equivalent of the drawing). This is a compact export illustration of the flow — **not a UML lifeline editor**: no activations, no alt/loop fragments, no return-message semantics, and line style (sync/async/data) appears only when the step resolved through a connection ref.
- Dark palette for the app itself stays dark-only (recorded decision); light exists for paper.
